## Завершённая задача 01

Реализация завершена и проверена на настоящей PostgreSQL 17 и Microsoft Edge.

Изменено:
- src/server/creation.ts и миграция 005: журнал результата по scope + UUID, транзакционная блокировка конкурентного повтора, 409 при изменённом теле.
- app.ts / live.ts: Idempotency-Key для создания нод, диалогов, персонажей; доступ проверяется до повтора, рассылка только для нового результата после COMMIT. Старые запросы без ключа сохраняют прежнее поведение.
- api.ts: запись намерения в IndexedDB до HTTP, один немедленный сетевой повтор, сохранение неясного исхода и восстановление при открытии проекта/диалога; идентичное незавершённое намерение использует старый ключ.
- session.ts: восстановление HTTP-создания нод при инициализации, отдельно от очереди текста/графа. Ошибка восстановления показывает уведомление.
- tests/app.test.ts: конкурентный повтор трёх видов объектов, конфликт тела, проверка доступа, перезапуск и подсчёт объектов через API.
- tests/browser/collaboration.spec.ts: сервер принимает создание, оба HTTP-ответа теряются, перезагрузка повторяет прежний ключ; независимый браузер видит одну ноду.

Следующая задача: [02](02.md), персональная отмена структуры. Точки входа уже просмотрены: graph.ts применяет команды под блокировкой диалога; live.ts хранит только payload_hash в graph_operations. Для Undo нужны сохранённые обратные изменения и проверяемые версии полей, чтобы не отменять последующие правки коллег; сравнения одних координат недостаточно (чужое изменение могло вернуть те же координаты). Текст и preview не восстанавливать из старого снимка: поздний текст должен сохраниться. Начало защитить, связи восстанавливать только после проверки правил. Код задачи 02 ещё не изменён.

Дополнительные проверки: изоляция одинакового ключа между проектами и запрет доступа чужой сессии; повтор создания после удаления ноды не воскрешает её. Браузерные сценарии потери ответов и перезагрузки покрывают все три типа создаваемых объектов. Очередь HTTP привязана к nodic-tab, чтобы одинаковые намерения разных вкладок не объединялись.

Ограничения реализации: создание самого проекта не изменялось (ответ содержит секреты доступа); записи журнала пока не очищаются. Автоматический повтор после двух сетевых ошибок происходит при повторном открытии, интерфейс показывает ошибку. Для будущего удаления проектов/диалогов продумать очистку журнала и оставшихся клиентских намерений. Изменения не закоммичены.

## Проверки и окружение

- npm run typecheck и npm run build прошли. Vite предупреждает о крупном чанке ~873 kB (задача 09).
- Vitest: 11/11 прошли с настоящей PostgreSQL 17.4.
- Playwright: 6/6 прошли в Microsoft Edge, включая независимые браузерные контексты.
- git diff --check: без ошибок.
- Рабочее дерево содержит все изменения задачи 01 и документы задач; коммит пока не создавался.
- Обычный exec_command падает до запуска оболочки (Windows CET). Чтение/запуск доступны через node_repl с node:fs/promises и child_process.execFile.
- Docker недоступен в этой sandbox-сессии. Для проверок создан отдельный временный кластер C:/Temp/nodic-test-pg установленными C:/Program Files/PostgreSQL/17/bin/initdb.exe и postgres.exe. База nodic, роль nodic, localhost:55432, trust только в этом тестовом кластере. Это не пользовательские данные.
- pg_ctl start не работает с sandbox-токеном; postgres.exe запускается напрямую с -D C:/Temp/nodic-test-pg -h 127.0.0.1 -p 55432 через скрытый child_process.spawn.
- tsx падает при os.userInfo() в sandbox. Для тестового процесса использован C:/Temp/nodic-test-user.cjs (перехватывает только ERR_SYSTEM_ERROR у os.userInfo и возвращает username CodexSandboxOffline). Запуск API: node --require C:/Temp/nodic-test-user.cjs --import tsx src/server/main.ts. Production-код и зависимости ради этого не менялись.
- Vite запущен обычным node node_modules/vite/bin/vite.js --host 127.0.0.1; Playwright использует готовый сервер.
- Для Playwright задан PLAYWRIGHT_CHANNEL=msedge, SystemRoot=C:/Windows, SystemDrive=C:, PROGRAMFILES=C:/Program Files и PROGRAMFILES(X86)=C:/Program Files (x86). Без SystemDrive поиск Edge ошибочно использует undefined. В обычной пользовательской оболочке достаточно PLAYWRIGHT_CHANNEL=msedge.
- Git требует параметр -c safe.directory=E:/Projects/nodic на каждый вызов; глобальная конфигурация не изменялась.
- gh не авторизован; GitHub Issues ещё не опубликованы. После восстановления доступа проверить существующие Issues, сопоставить карточки и опубликовать недостающие через gh --body-file; сохранить ссылки без дублей.

Тестовые API/Vite остановлены после проверки. Временный кластер PostgreSQL остановлен через pg_ctl; его данные оставлены для следующего запуска.
