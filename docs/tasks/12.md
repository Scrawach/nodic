# 12. Уменьшить стоимость рассылки изменений графа

Статус: не начата. Приоритет: P1; triage: ready-for-agent. GitHub Issue: не опубликована. 2026-09-15 проверены открытые Issues (есть только #1); автоматическая проверка разрешений отклонила публикацию этого локального документа из-за отсутствия отдельного одобрения внешнего раскрытия деталей. Нужна авторизация пользователя на публикацию подготовленной карточки; обход отказа не выполнялся.

## Проблема

[Профиль 09](../research/load-profile.md) на 1000 нод / 998 связей / 10 авторов: каждое движение отправляет полный graph около 632 KB, затем отдельный positions. Это около 6.3 MB на одну операцию для десяти соединений. В первом прогоне p95 ACK движения 10.40 s, доставки 10.15 s против бюджетов 250/300 ms. По коду `src/server/live.ts` broadcast сериализует полный снимок заново для каждого автора. Профиль показывает стоимость и задержки, но не доказывает долю конкретной причины: клиентские кадры тоже перегружены.

## Работа

1. Добавить раздельные измерения очереди/COMMIT/сериализации и клиентского приёма, не меняя гарантию ACK после COMMIT.
2. Для обычного перемещения отправлять компактное изменение вместо полного графа; сохранить начальный снимок, безопасное восстановление после reconnect и совместимость истории/Undo/Redo.
3. Проверить, можно ли сериализовать одно сообщение один раз на комнату; не вводить временные ACK до долговечной записи.

## Критерии готовности

- Перемещение одной ноды передаёт не более 2 KB полезной нагрузки каждому автору (без presence) независимо от общего размера графа; точные поля и размер проверить профилем.
- Все 10 авторов получают одинаковое итоговое состояние; повтор и восстановление не теряют/дублируют команды; независимые browser contexts, только публичные операции.
- Повторить два полных профиля 09 и сравнить p50/p95 с сохранёнными baseline. Общий бюджет ACK ≤250 ms / доставка ≤300 ms остаётся; если блокирует клиентская стоимость, явно связать с задачей 13 и не объявлять весь performance gate пройденным.
- Typecheck, серверные/e2e тесты и build проходят. Обновить отчёт и PROGRESS.

Зависимость: 09 (завершённое измерение). Связана с [13](13.md); обе блокируют подтверждение отзывчивости 1000/10 для v1.
