# Разделить совместный текст и изменения структуры

Для Nodic выбираем Yjs 13 для текста и серверную последовательную обработку команд для структуры диалога, с PostgreSQL как постоянным хранилищем. Одновременное объединение произвольных связей может нарушить правило «несколько выходов только в варианты», поэтому сервер проверяет структурную команду относительно последнего принятого графа; текст объединяется независимо, без блокировки автора.

Для отмены используем локальные истории вкладок: Yjs UndoManager для текста и проверяемые обратные команды для структуры. Удаление скрывает ноду, сохраняя текст для восстановления, а обратная команда не перезаписывает последующие чужие изменения.

## Основание и границы

Прототип с реальными Yjs-репликами подтвердил объединение ввода, персональную отмену и сохранение пришедшего текста при восстановлении ноды. Последовательная модель команд отклонила конкурентное недопустимое ветвление. Это выбор архитектуры для первого рабочего среза, а не подтверждение надёжности сети или производительности: [результаты](../research/collaboration-prototype.md).

Альтернатива «весь граф в CRDT» потребовала бы отдельного разрешения конфликтов связей и обработки скрытых/отклонённых связей после слияния. Альтернатива «весь текст целой строкой через сервер» теряла бы конкурентный ввод без дополнительного алгоритма совместного текста.
