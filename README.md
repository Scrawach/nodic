# Nodic

Совместный веб-редактор нарративных диалогов. [Спецификация](docs/specs/nodic-v1.md) · [Архитектура](docs/architecture.md).

## Первый рабочий срез

Реализованы создание проекта и диалога с началом, ссылки владельца и редактора, добавление нод, доска с миникартой и совместный модальный редактор текста. Два автора могут одновременно писать в одной реплике, видеть курсоры и отменять свой ввод. Подтверждение сохранения выдаётся после записи в PostgreSQL; ожидающие текстовые операции сохраняются в IndexedDB и повторяются после переподключения.

Это ещё не весь Nodic v1. Соединение, перемещение и удаление нод, общая история структурных действий, персонажи, управление несколькими диалогами и нагрузочная проверка пока не реализованы. [Границы среза и проверки](docs/first-slice.md).

## Локальный запуск

Нужны Node.js 22.12+ (или 24 LTS), npm и работающий Docker Desktop с Linux containers.

```sh
npm ci
npm run db:up
npm run dev
```

Открыть [http://127.0.0.1:5173](http://127.0.0.1:5173). Создать проект, добавить реплику и открыть её двойным кликом. Через «Поделиться» скопировать ссылку редактора и открыть в другом браузере или приватном окне.

Docker публикует PostgreSQL только на `127.0.0.1:55432`. Его том сохраняется при `npm run db:down`. Локальные значения подключения заданы в `.env.example`; при необходимости скопировать его в `.env` и изменить настройки. Локальный пароль из примера предназначен только для разработки.

Ссылку владельца стоит сохранить отдельно: входа по почте и восстановления доступа в этом срезе ещё нет.

## Проверки

После запуска БД:

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Если установлен Microsoft Edge, можно задать `PLAYWRIGHT_CHANNEL=msedge`. В Windows cmd: `set PLAYWRIGHT_CHANNEL=msedge&&npm run test:e2e`.

Серверные тесты используют настоящую PostgreSQL и создают изолированные проекты с новыми идентификаторами. Можно направить их в отдельную заранее созданную базу через `DATABASE_URL`; тесты не удаляют существующие данные. Playwright запускает dev-сервер автоматически либо использует уже запущенный локальный сервер.

## Собранное приложение

`npm run build` создаёт клиент в `dist/`. Команда `npm start` запускает API и раздаёт собранный клиент. Для такого запуска установить `PUBLIC_ORIGIN=http://127.0.0.1:3001` (либо фактический HTTPS origin). Настройки `HOST`, `PORT`, `DATABASE_URL` читаются из окружения или `.env`.

Первый срез предназначен для локальной проверки. Публичное развёртывание потребует лимитов запросов, политики сессий, наблюдаемости, резервного копирования и проверки отказов.
