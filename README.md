# Nodic

Совместный веб-редактор нарративных диалогов. [Спецификация](docs/specs/nodic-v1.md) · [Архитектура](docs/architecture.md).

## Первый рабочий срез

Фронтенд оформлен в стиле Midline: почти чёрная монохромная оболочка, Courier New, прямоугольные панели и спокойная статическая текстура на главной. Цвета персонажей и авторов сохраняют своё значение. Формы и оболочка адаптированы к ширине 360px; рабочая доска предназначена для настольного управления.

Реализованы создание проекта и нескольких диалогов, ссылки владельца и редактора, создание, перемещение, соединение и удаление нод, настройка формы связей, создание и выбор персонажей, доска с миникартой и совместный модальный редактор текста. Два автора могут одновременно писать в одной реплике, видеть курсоры и отменять свой ввод. Подтверждение сохранения выдаётся после записи в PostgreSQL; ожидающие текстовые операции сохраняются в IndexedDB и повторяются после переподключения.

Это ещё не весь Nodic v1. Доступны общий справочник персонажей, управление проектами и диалогами, копирование групп, единая история текста/графа и присутствие на доске. [Матрица 27 пользовательских историй](docs/v1-verification.md) содержит реализацию, проверки и остатки, включая неполную область персональной отмены. [Профиль 1000 нод / 10 авторов](docs/research/load-profile.md) выявил задержки редактирования, пропуски кадров и превышение бюджета памяти; performance gate не пройден. [Границы среза и проверки](docs/first-slice.md).

## Локальный запуск

### Всё в Docker

Нужны работающий Docker Engine/Desktop, Docker Compose и `make`. Node.js на компьютере не требуется.

```sh
make up
```

Команда собирает приложение, запускает PostgreSQL, бэк и фронт в фоне и ждёт их готовности. Открыть [http://127.0.0.1:5173](http://127.0.0.1:5173). При первом запуске скачиваются образы и npm-зависимости. После изменения исходников снова выполнить `make up`, чтобы пересобрать приложение.

```sh
make logs     # логи бэка, фронта и БД; Ctrl+C завершает только просмотр
make status   # состояние контейнеров
make restart  # перезапустить бэк и фронт
make down     # остановить контейнеры, сохранив данные проектов
make check    # типы, серверные тесты и production-сборка
```

Без `make`: `docker compose --profile dev up --build -d --wait`; остановка — `docker compose --profile dev down`. Данные БД хранятся в именованном томе. Порты `5173`, `3001` и `55432` доступны только на этом компьютере. Для Docker подключение к БД задаётся в `compose.yaml`; локальный `.env` в образ не копируется.

Сеть проекта явно использует `172.29.240.0/24`, чтобы широкие маршруты VPN не мешали Docker выбирать подсеть. Если этот диапазон уже занят вашей сетью, задайте свободный через `NODIC_SUBNET` перед запуском.

На Linux Docker daemon должен быть запущен (`sudo systemctl start docker`), а пользователь должен иметь доступ к Docker. Если доступ есть только через sudo и Compose установлен системно, используйте `sudo make up`. Для Compose в пользовательском каталоге: `make COMPOSE="sudo $HOME/.docker/cli-plugins/docker-compose" up` (аналогично для `down`, `logs` и других команд).

Реплики показывают крупные имя персонажа и текст без служебного заголовка. На доске видно до шести строк реплики и четырёх строк варианта; длинный текст переносится и получает многоточие. Полный текст доступен по двойному клику. Варианты имеют более узкую треугольную форму.

Средняя кнопка мыши панорамирует доску, в том числе поверх ноды; обычный курсор — стрелка. ЛКМ по пустому полю выделяет рамкой полностью охваченные ноды, Shift+клик добавляет к выделению. Перетаскивание выбранной группы сохраняется и отменяется одним действием; ПКМ по рамке открывает меню группы. Масштаб и миникарта доступны независимо от выделения.

Для ручной проверки создайте проект. ПКМ на пустом поле открывает меню добавления нод с иконками. Потяните из выходного гнезда одной ноды во входное другой — появится связь со стрелкой. Саму кривую можно перетаскивать: рядом с прямой между гнёздами она выпрямляется; двойной клик по связи сбрасывает форму. ПКМ на ноде позволяет удалить её (кроме начала), ПКМ на связи — удалить связь или сбросить её форму. Двойной клик по реплике открывает текст и выбор/создание персонажа. Цвет персонажа можно выбрать при создании или изменить кнопкой «Сохранить цвет»; он общий для всех его реплик. В боковой панели над диалогами расположен список персонажей с цветом рядом с именем. «Новый персонаж» открывает создание; выбор имени — редактирование имени/цвета и удаление с подтверждением. Обновления видны соавторам, удаление закрывает открытый редактор персонажа. Длинный список прокручивается до диалогов; «Новый диалог» находится под ними. Через «Поделиться» откройте ссылку редактора в приватном окне и проверьте синхронизацию, затем обновите обе страницы.

### Бэк и фронт на компьютере

Нужны Node.js 22.12+ (или 24 LTS), npm и работающий Docker Desktop с Linux containers.

```sh
npm ci
npm run db:up
npm run dev
```

Открыть [http://127.0.0.1:5173](http://127.0.0.1:5173). Создать проект, добавить реплику и открыть её двойным кликом. Через «Поделиться» скопировать ссылку редактора и открыть в другом браузере или приватном окне.

Docker публикует PostgreSQL только на `127.0.0.1:55432`. Его том сохраняется при `npm run db:down`. Локальные значения подключения заданы в `.env.example`; при необходимости скопировать его в `.env` и изменить настройки. Локальный пароль из примера предназначен только для разработки.

Ссылку владельца стоит сохранить отдельно: входа по почте и восстановления доступа в этом срезе ещё нет.

## Проверки

После запуска БД:

```sh
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Если установлен Microsoft Edge, можно задать `PLAYWRIGHT_CHANNEL=msedge`. В Windows cmd: `set PLAYWRIGHT_CHANNEL=msedge&&npm run test:e2e`.

Серверные тесты используют настоящую PostgreSQL и создают изолированные проекты с новыми идентификаторами. Можно направить их в отдельную заранее созданную базу через `DATABASE_URL`; тесты не удаляют существующие данные. Playwright запускает dev-сервер автоматически либо использует уже запущенный локальный сервер.

## Собранное приложение

`npm run build` создаёт клиент в `dist/`. Команда `npm start` запускает API и раздаёт собранный клиент. Для такого запуска установить `PUBLIC_ORIGIN=http://127.0.0.1:3001` (либо фактический HTTPS origin). Настройки `HOST`, `PORT`, `DATABASE_URL` читаются из окружения или `.env`.

Рабочий срез предназначен для локальной проверки. Отказы записи и восстановления проверены в описанных ниже границах. Публичное развёртывание потребует лимитов запросов, политики сессий, наблюдаемости, резервного копирования и проверки восстановления из резервной копии. Комнаты рассчитаны на один API-процесс.

## Граница сохранения

«Сохранено» означает серверный ACK после PostgreSQL COMMIT. До завершения записи очереди в IndexedDB изменение может потеряться при закрытии вкладки; в этот момент показывается «Сохраняется…» и данные ещё не отправляются. Записанная очередь повторяется при переподключении, перезагрузке или восстановлении той же вкладки с её sessionStorage. Новая вкладка не забирает очередь старой. Потеря ACK и перезапуск API не дублируют принятые операции. [Подробные гарантии и проверенные отказы](docs/first-slice.md#гарантия-сохранения-и-восстановления).
